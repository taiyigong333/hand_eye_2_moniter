# `rot` 与标定板姿态关系

本文专门解释三个容易混淆的问题：

1. `aruco_id_map_new.json` 里的 `rot` 会如何影响手眼标定。
2. 建立标定板映射时的标定板姿态，和手眼标定采集时的标定板姿态是否必须一样。
3. 手眼标定时机械臂末端需要旋转，这和“标定板旋转会不会影响映射”之间是什么关系。

结论先说：

- `rot` 描述的是单个 marker 在标定板坐标系里的角点顺序，不是采集时整块标定板相对相机的姿态。
- 建映射时的参考照片姿态和手眼标定时的相机观察姿态不需要一样。
- 手眼标定时，末端相机相对标定板发生旋转是正常且必要的。
- 只要实体标定板本身没有重新贴、重新排布、重新定义左上角和行列方向，整块标定板在相机前怎么旋转都不需要重新生成 `rot`。

## 1. `rot` 到底是什么

`assets/boards/aruco_id_map_new.json` 中每个条目格式是：

```json
{
  "0": [14, 18, 2]
}
```

含义是：

- `"0"`：ArUco marker ID 为 `0`。
- `14`：这个 marker 在标定板第 14 行，即 `row=14`。
- `18`：这个 marker 在标定板第 18 列，即 `col=18`。
- `2`：这个 marker 的 3D 角点顺序需要循环偏移 2 次，即 `rot=2`。

`row` / `col` 负责“marker 在标定板上的哪个格子”。

`rot` 负责“这个 marker 的四个角，应该按什么顺序对应 OpenCV 检测到的四个 2D 角点”。

所以 `rot` 不是机器人末端姿态，也不是相机姿态，也不是本轮采集时标定板相对相机旋转了多少度。

## 2. `rot` 在代码里如何发挥作用

运行 `calib.py` 时，代码先读取映射文件：

```text
assets/boards/aruco_id_map_new.json
```

然后对每个检测到的 marker 做下面的事情：

```text
OpenCV 检测到 marker ID 和 2D 图像角点
        ↓
用 marker ID 查 aruco_id_map_new.json
        ↓
row / col 确定 marker 在标定板坐标系里的 3D 位置
        ↓
tag_size / cell_size 生成理想 3D 角点
        ↓
rot 调整 3D 角点数组顺序
        ↓
3D 角点和 2D 角点一一对应
        ↓
solvePnP() 求 T_cam_board
```

对应代码在 `calib.py` 中的核心逻辑是：

```text
corners = [
  TL,
  TR,
  BR,
  BL
]

corners = np.roll(corners, -rot, axis=0)
```

也就是说，`rot` 只改变四个 3D 角点在数组里的排列顺序，不改变这个 marker 的中心位置，也不改变 `row` / `col`。

## 3. `rot` 错了会怎样影响手眼标定

手眼标定依赖每张图里估计出来的标定板位姿 `T_cam_board`。而 `T_cam_board` 来自：

```text
solvePnP(标定板上的 3D 角点, 图像中的 2D 角点)
```

如果 `rot` 错了，程序会把图像里的 2D 角点对应到错误的 3D 角点。例如本来应该是：

```text
2D 第 1 个角点 <-> 3D 左上角
2D 第 2 个角点 <-> 3D 右上角
2D 第 3 个角点 <-> 3D 右下角
2D 第 4 个角点 <-> 3D 左下角
```

但 `rot` 错后可能变成：

```text
2D 第 1 个角点 <-> 3D 右下角
2D 第 2 个角点 <-> 3D 左下角
2D 第 3 个角点 <-> 3D 左上角
2D 第 4 个角点 <-> 3D 右上角
```

这会直接污染 `solvePnP()` 输入，后果包括：

- 单张图的 `reproj_rmse` 变大。
- `debug_vis/*_end.jpg` 或 `debug_vis/*_fixed.jpg` 中红色重投影点和绿色检测点错位。
- `T_cam_board` 方向或位置错误。
- 腕部相机手眼结果 `T_ee_cam_end` 被带偏。
- 标定板基座位姿 `T_base_board` 被带偏。
- 固定相机外参 `T_base_cam_fixed` 被带偏。

所以 `rot` 错不是小问题，它会从 PnP 阶段一路传递到最终手眼外参。

## 4. 建映射时的板姿态和手眼标定时的板姿态是否必须一样

不必须一样。

建映射时用 `assets/boards/board.jpg`，目的是确定这块实体板的内部结构：

```text
marker ID -> row / col / rot
```

它回答的是：

```text
ID=0 这个 marker 在板上的哪个格子？
它的四个角点顺序相对标定板坐标系应该怎么排？
```

手眼标定采集时，`calib.py` 用相机图像实时估计：

```text
这块板当前相对相机是什么姿态？
```

这两个问题不是同一个问题。

只要实体板本身没有变，建映射时的照片可以是正着拍、斜着拍、远一点拍、近一点拍；手眼标定时也可以从不同角度观察。`solvePnP()` 本来就是用来从当前图像中估计标定板相对相机的实时姿态。

## 5. 什么样的“旋转标定板”不会影响映射

下面这些不会要求重新生成 `aruco_id_map_new.json`：

- 手眼标定时，相机从不同角度看同一块固定标定板。
- 机器人末端旋转，导致腕部相机相对固定标定板发生旋转。
- 采集时整块标定板在图像中看起来倾斜、透视、上下左右方向变化。
- 建映射参考照片中的整块板和手眼采集图像中的整块板角度不同。

原因是：这些变化都属于“整块板作为一个刚体相对相机发生了姿态变化”。板内部的 ID 排布、row/col、marker 角点顺序没有变。

`calib.py` 会通过每张图的 2D 角点和固定的 3D 板模型求出当前的 `T_cam_board`，所以这种相对姿态变化正是 PnP 和手眼标定要处理的对象。

## 6. 什么样的“旋转标定板”会影响映射

下面这些会影响映射，通常需要重新生成 `aruco_id_map_new.json`：

- 重新打印或换了一块标定板。
- 把 marker 贴纸重新粘贴，导致 ID 排布变化。
- 把整张打印纸旋转 90 度后重新固定到另一块背板上，同时仍然沿用旧的“左上角、row/col”定义。
- 裁切后重新定义了有效棋盘区域四角。
- `top_left_is_tag`、`grid_cols`、`grid_rows`、`tag_size`、`cell_size` 与实际板不一致。
- 用另一张参考照片重新点击四角时，左上、右上、右下、左下顺序点错，导致板坐标系定义变了。

这些变化改变的不是“相机怎么看板”，而是“板坐标系如何定义、ID 在板上的位置和角点顺序是什么”。这会让 `row` / `col` / `rot` 失效。

## 7. 手眼标定为什么需要末端旋转

眼在手上标定需要机器人末端产生足够丰富的相对运动。当前项目里腕部相机会随着 UR7e 末端运动，不同样本满足：

```text
T_base_board = T_base_ee_i @ T_ee_cam_end @ T_cam_board_i
```

其中：

- `T_base_ee_i` 来自机器人 TCP。
- `T_cam_board_i` 来自相机图像和 `solvePnP()`。
- `T_ee_cam_end` 是要求的腕部相机安装外参。
- `T_base_board` 是固定标定板在机器人基座下的位姿，理论上每个样本都应一致。

如果机器人只平移、几乎不旋转，手眼方程的旋转约束会很弱，结果容易不稳定。因此采集时要求末端从不同方向、不同角度观察同一块固定标定板。

这和 `rot` 不是一回事：

- 末端旋转：改变相机和整块标定板之间的相对姿态，是采集数据需要的运动。
- `rot`：描述单个 marker 四个角点在板模型中的顺序，是标定板几何先验的一部分。

末端相机相对标定板旋转不会改变 `rot`。它只会改变每张图估计出来的 `T_cam_board_i`。

## 8. 固定标定板和移动标定板的区别

当前项目的双相机联合流程默认假设：标定板在整轮采集期间保持静止。

也就是说，手眼采集时允许：

```text
相机动，标定板不动
```

不应该发生：

```text
采集过程中标定板被移动、拿起、重新放置或支架松动
```

如果标定板在采集过程中作为一个刚体被移动，`aruco_id_map_new.json` 本身仍然可能是对的，因为板内部结构没变；但当前手眼标定链路里的固定板假设会被破坏，`T_base_board consistency` 通常会发散，最终手眼结果不可信。

所以要区分：

| 变化 | 是否影响 `rot` / 映射 | 是否影响本项目手眼标定 |
| --- | --- | --- |
| 建映射照片和采集照片角度不同 | 不影响 | 不影响，PnP 会估计当前姿态 |
| 末端相机绕标定板多角度观察 | 不影响 | 需要这样做 |
| 整块标定板采集前换了摆放角度，但采集全程固定 | 不影响映射 | 通常可以，但要确保两台相机都能看见 |
| 采集过程中标定板被移动 | 不影响映射 | 会破坏固定板假设 |
| 重新贴 marker 或重定义板左上角 | 影响 | 必须重建映射 |
| `rot` 写错 | 影响 | PnP 和手眼都会被带偏 |

## 9. 实操判断

如果你只是问：

```text
我生成映射时板是正着拍的，手眼采集时板在图像里斜了、转了、机器人末端也转了，这要不要重做映射？
```

答案是：不需要。只要实体板内部没有变，映射仍然有效。

如果你问：

```text
我把板重新打印、重新贴、旋转后重新固定，并且旧的 row/col/rot 可能不再对应这块板了，要不要重做映射？
```

答案是：需要。

如果你看到：

```text
debug_vis 里红绿点旋转错位，或者 aruco_id_map_new.jpg 里 rot/row/col 明显不符合实体板
```

优先重新检查 `aruco_id_map_new.json`、`aruco_id_map_new.jpg`、四角点击顺序和 `rot`，不要先调手眼结果矩阵。
