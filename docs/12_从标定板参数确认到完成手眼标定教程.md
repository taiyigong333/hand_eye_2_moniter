# 从标定板参数确认到完成手眼标定教程

本文按一次真实重新标定的顺序组织：先确认标定板参数，再确认机器人、相机和采样配置，最后完成采集、计算和结果检查。它适用于当前仓库的 UR7e + 双 RealSense 联合标定流程。

当前项目的默认目标是同时得到三组结果：

- `T_ee_cam_end.matrix_4x4`：末端腕部相机到 UR 末端坐标系的外参。
- `T_base_board.matrix_4x4`：标定板到 UR 基座坐标系的外参。
- `T_base_cam_fixed.matrix_4x4`：外部固定相机到 UR 基座坐标系的外参。

本项目统一使用 `T_A_B` 表示“从坐标系 B 到坐标系 A”的变换，即 `p_A = T_A_B @ p_B`。

## 1. 准备工作目录和环境

在仓库根目录执行：

```powershell
cd F:\research\guo\hand-eye\calibration
```

优先使用本机已配置的 `hand_eye` 环境：

```powershell
F:\Anaconda\Anaconda3\envs\hand_eye\python.exe calib.py --help
F:\Anaconda\Anaconda3\envs\hand_eye\python.exe scripts\collect_and_calibrate.py --help
```

如果环境需要重建：

```powershell
conda env update -n hand_eye -f environment.yml
conda activate hand_eye
```

正式连接硬件前，先确认：

- UR7e 与 PC 网络互通。
- UR 控制柜启用 Dashboard 和 RTDE。
- 两台 RealSense 没有被 RealSense Viewer 或其他程序占用。
- 标定板固定、平整，采集全程不会移动。

## 2. 确认标定板参数

当前默认实体标定板参数来自 `configs/live_collection.example.json` 的 `calibration` 字段：

| 参数 | 当前值 | 含义 |
| --- | --- | --- |
| `board_layout` | `interleaved_checker` | ArUco marker 与黑色格交错排列 |
| `grid_cols` | `20` | 棋盘总列数，包含 marker 格和黑色格 |
| `grid_rows` | `15` | 棋盘总行数，包含 marker 格和黑色格 |
| `tag_size` | `0.015` | ArUco marker 外层黑色正方形边长，单位米 |
| `cell_size` | `0.019` | 单个棋盘格边长，单位米 |
| `aruco_dict` | `DICT_6X6_250` | OpenCV ArUco 检测字典 |
| `top_left_is_tag` | `true` | 有效棋盘区域左上角是否为 marker 格 |
| `id_map_json` | `assets/boards/aruco_id_map_new.json` | marker ID 到棋盘行列和角点旋转的映射 |

这些参数必须和实体板一致，尤其是 `tag_size` 和 `cell_size`。尺寸写错会直接按比例影响平移结果；`id_map_json` 用错会让 PnP 的 2D-3D 对应关系错误。

## 3. 判断是否需要重做标定板 ID 映射

如果只是用当前仓库已有的实体板、贴放方式和 `assets/boards/aruco_id_map_new.json`，可以先不重做映射，直接进入第 5 节。

以下情况必须重做：

- 换了新标定板。
- 重新打印、裁切、覆膜、粘贴或旋转了标定板。
- marker ID 排布和仓库里的 `assets/boards/aruco_id_map_new.json` 不一致。
- `debug_vis/*_end.jpg` 或 `debug_vis/*_fixed.jpg` 中绿色检测点和红色重投影点系统性错位，并怀疑是板参数或映射错误。

先拍一张清晰的整板图，建议保存为：

```text
assets/boards/board.jpg
```

拍摄要求：

- 有效棋盘区域四角完整可见。
- 图像清晰，避免强反光、遮挡和运动模糊。
- 标定板可有透视，但四角像素必须能准确点击或读出。

## 4. 生成或复核 `id_map_json`

有 GUI 时，可以让脚本弹窗点击四角；为了可复现，推荐显式传入 `--corners`。四角顺序必须是左上、右上、右下、左下。

```powershell
F:\Anaconda\Anaconda3\envs\hand_eye\python.exe tools\make_aruco_id_map.py assets\boards\board.jpg `
  --aruco_dict DICT_6X6_250 `
  --grid_cols 20 `
  --grid_rows 15 `
  --top_left_is_tag true `
  --corners "589,77 3757,203 3849,2603 444,2592" `
  --tag_size 0.015 `
  --cell_size 0.019 `
  --max_cell_dist 0.55 `
  --out assets\boards\aruco_id_map_new.json `
  --vis assets\boards\aruco_id_map_new.jpg
```

生成后打开：

```text
assets/boards/aruco_id_map_new.jpg
```

重点检查：

- 每个 marker 的标注类似 `id23->r12c12rot2`，行列位置符合实体板。
- 蓝色检测中心和红色映射中心距离较近。
- 没有大面积 marker 被跳过。
- 没有明显行列反转、左右镜像或四角顺序错误。

如果检查图不对，不要继续采集。优先修正 `--corners`、`grid_cols`、`grid_rows`、`top_left_is_tag`、`tag_size`、`cell_size` 后重新生成。

## 5. 确认机器人和相机配置

正式采集前打开：

```text
configs/live_collection.example.json
```

机器人侧重点确认：

| 字段 | 当前示例 | 检查点 |
| --- | --- | --- |
| `robot.host` | `192.168.1.88` | PC 能访问该 UR7e IP |
| `robot.dashboard_port` | `29999` | Dashboard 端口可用 |
| `robot.program` | `autoHandEye2.urp` | 示教器里已经保存这个 URP |
| `robot.load_program` | `true` | 是否允许 PC 自动 load |
| `robot.play_after_load` | `true` | 是否允许 PC 自动 play |

相机侧当前约定：

| 角色 | 字段 | 当前示例 | 保存文件 |
| --- | --- | --- | --- |
| 末端腕部相机 | `role=end` / `camera_index=0` | D405，`1280x720@30` | `cam0_wrist.png` |
| 外部固定相机 | `role=fixed` / `camera_index=1` | D435i，`1920x1080@30` | `cam1_main.png` |

必须确认：

- `cameras[].serial` 和实际插入的 RealSense 序列号一致。
- `cameras[].color_width`、`color_height`、`fps` 和实际启动 profile 一致。
- `refresh_intrinsics_from_device` 为 `true` 时，程序会用当前 active profile 覆盖 `cameras[].intrinsics_path`。
- `calibration.fixed_camera_index=1`、`calibration.end_camera_index=0` 没有写反。

采样侧重点确认：

| 字段 | 当前示例 | 建议 |
| --- | --- | --- |
| `sampling.mode` | `timed` | 自动采样用 `timed`，人工控制姿态用 `manual` |
| `sampling.interval_s` | `2.0` | 定时采样时确保机械臂已经静止 |
| `sampling.max_samples` | `35` | 建议至少 15 组有效样本，姿态要有旋转变化 |
| `calibration.max_reproj_rmse` | `10.0` | 单相机单样本重投影 RMSE 过滤阈值 |
| `calibration.output_dir` | `outputs/live_calibration` | 保持默认会自动追加时间戳 |

## 7. 采集手眼标定样本

推荐先用手动模式做第一轮，因为可以在每个姿态稳定后再保存：

```powershell
F:\Anaconda\Anaconda3\envs\hand_eye\python.exe scripts\collect_and_calibrate.py `
  --config configs\live_collection.example.json `
  --mode manual
```

手动模式下：

- 按 `c` 保存一组样本。
- 按 `q` 结束采集。
- 预览窗口聚焦时也可以直接按 `c` / `q`。

如果 URP 已经在示教器手动加载并启动，只想让 PC 读取 RTDE 和相机：

```powershell
F:\Anaconda\Anaconda3\envs\hand_eye\python.exe scripts\collect_and_calibrate.py `
  --config configs\live_collection.example.json `
  --mode manual `
  --skip_robot_program
```

如果想定时采集并在结束后自动标定：

```powershell
F:\Anaconda\Anaconda3\envs\hand_eye\python.exe scripts\collect_and_calibrate.py `
  --config configs\live_collection.example.json
```

采集姿态要求：

- 标定板在整轮采集期间保持静止。
- 两台相机每个有效样本都能看到足够数量的 marker。
- 机械臂保存样本时必须静止。
- 姿态要包含明显旋转变化，不能只平移。
- 末端相机应从不同距离、不同角度观察标定板，尽量覆盖图像中心和边缘。
- 固定相机不能被碰动，镜头、支架和标定板都要保持稳定。

## 8. 采集数据结构

默认样本目录为：

```text
data/live_capture/
├── capture_session_config.json
├── sample_000/
│   ├── cam0_wrist.png
│   ├── cam1_main.png
│   └── pose.json
├── sample_001/
│   ├── cam0_wrist.png
│   ├── cam1_main.png
│   └── pose.json
└── ...
```

`calib.py` 主要读取：

- `pose.json/tcp_pose`：UR RTDE 的 `[x, y, z, rx, ry, rz]`。
- `pose.json/images`：两台相机图像、`camera_index`、`role` 和内参路径。
- `cam0_wrist.png`：末端相机图像。
- `cam1_main.png`：固定相机图像。

`capture_session_config.json` 是本轮配置快照，建议和输出结果一起保留。

## 9. 运行标定计算

如果采集命令没有加 `--skip_calibration`，采集结束后会自动调用 `calib.py`。

如果只想先采集，之后手动计算，可先运行：

```powershell
F:\Anaconda\Anaconda3\envs\hand_eye\python.exe scripts\collect_and_calibrate.py `
  --config configs\live_collection.example.json `
  --mode manual `
  --skip_calibration
```

再手动调用：

```powershell
F:\Anaconda\Anaconda3\envs\hand_eye\python.exe calib.py `
  --dataset_dir data/live_capture `
  --fixed_camera_index 1 `
  --end_camera_index 0 `
  --intr_fixed configs/intr_d435i_1920x1080.json `
  --intr_end configs/intr_d405_1280x720.json `
  --board_layout interleaved_checker `
  --grid_cols 20 `
  --grid_rows 15 `
  --tag_size 0.015 `
  --cell_size 0.019 `
  --aruco_dict DICT_6X6_250 `
  --top_left_is_tag true `
  --id_map_json assets\boards\aruco_id_map_new.json `
  --max_reproj_rmse 10.0 `
  --translation_scale 1.0 `
  --output_dir outputs\my_live_calibration
```

`calib.py` 的内部顺序是：

1. 读取 `pose.json`，把 `tcp_pose` 转成 `T_base_ee`。
2. 两台相机分别检测 ArUco 角点。
3. 结合相机内参、标定板尺寸和 `id_map_json`，用 `solvePnP` 求 `T_cam_end_board` 和 `T_cam_fixed_board`。
4. 用 `--max_reproj_rmse` 过滤坏样本。
5. 调用 OpenCV `calibrateHandEye` 求 `T_ee_cam_end`。
6. 用腕部相机结果估计固定标定板的 `T_base_board`。
7. 用固定相机观测反推出 `T_base_cam_fixed`。

## 10. 检查输出结果

默认自动标定输出目录类似：

```text
outputs/live_calibration_YYYYMMDD_HHMMSS/
├── calibration_result.json
├── dynamic_end_camera_poses.json
└── debug_vis/
    ├── 000_end.jpg
    ├── 000_fixed.jpg
    └── ...
```

按这个顺序检查：

1. 看终端里的总样本数和有效样本数。有效样本太少时，不要直接使用结果。
2. 看每帧 `reproj_rmse`。大量样本超过阈值时，先排查内参、标定板参数、`id_map_json` 和图像清晰度。
3. 打开 `debug_vis/*_end.jpg` 和 `debug_vis/*_fixed.jpg`。绿色检测点和红色重投影点应基本重合。
4. 看终端中的 `T_base_board consistency` 和 `T_base_cam_fixed consistency`。离散越小，跨样本越一致。
5. 打开 `calibration_result.json`，确认 `num_valid_samples`、`board_config`、`T_ee_cam_end`、`T_base_board`、`T_base_cam_fixed` 都存在。

固定相机下游抓取通常应读取：

```text
calibration_result.json/T_base_cam_fixed/matrix_4x4
```

它的含义是“固定相机坐标系到机器人基座坐标系”。把固定相机坐标下的点转到基座时使用：

```text
p_base = T_base_cam_fixed @ p_cam_fixed
```

不要误用 `T_ee_cam_end` 或 `T_base_board`。

## 11. 通过标准

一轮标定至少要满足：

- 使用的标定板尺寸、字典、ID 映射和实体板一致。
- 采集配置中的相机角色、序列号、分辨率、内参路径没有写反。
- 有足够有效样本，且姿态包含明显旋转变化。
- `debug_vis` 中检测点和重投影点基本重合。
- `T_base_board consistency` 和 `T_base_cam_fixed consistency` 没有明显发散。
- `calibration_result.json` 中三组核心矩阵都存在。
- 已记录本轮配置、数据目录、输出目录和最终使用的 `T_base_cam_fixed.matrix_4x4`。

如果任一项不满足，应先修正输入链路后重采，不要靠手工微调矩阵掩盖问题。

## 12. 常见返工原因

| 现象 | 优先排查 |
| --- | --- |
| marker 检测数量少 | 曝光、模糊、遮挡、距离过远、`aruco_dict` 写错 |
| RMSE 普遍偏大 | 内参分辨率不匹配、`tag_size` / `cell_size` 错、`id_map_json` 错、四角顺序错 |
| 有效样本很多但一致性差 | 机器人运动中采样、标定板或相机支架松动、姿态缺少旋转变化、TCP 和图像不同步 |
| 固定相机结果方向不对 | 把 `T_base_cam_fixed` 当成 `T_cam_fixed_base` 使用，或下游误读矩阵方向 |
| 结果平移尺度不合理 | 米和毫米混用、标定板尺寸写错、`translation_scale` 使用不当 |

每次正式标定后建议记录：

- 当前 Git 提交号。
- 使用的 `configs/live_collection.example.json` 或本轮配置副本。
- 使用的 `assets/boards/board.jpg`、`assets/boards/aruco_id_map_new.json` 和检查图。
- 采集数据目录，例如 `data/live_capture`。
- 输出目录，例如 `outputs/live_calibration_20260530_153000`。
- `num_total_samples`、`num_valid_samples`、RMSE 范围和一致性统计。
- 最终用于下游的 `T_base_cam_fixed.matrix_4x4`。
